# Documentation site toolchain (docs/ → GitHub Pages).
#
# PRIMARY: Zensical — the successor to MkDocs Material, written by the same
# team (Martin Donath / squidfunk) and released under MIT. It is Rust+Python,
# reads this repo's mkdocs.yml unchanged, and keeps the Material look via
# `variant: classic` in that file. Link validation is on by default and
# `--strict` aborts the build on any warning, so the CI gate is preserved.
#
#   zensical serve              # local preview, http://127.0.0.1:8000
#   zensical build --strict     # the check CI runs
#
# VERSIONING: mike (squidfunk fork). Upstream mike only knows `mkdocs build`;
# the fork calls `zensical build` instead, so it keeps the multi-version
# gh-pages workflow working under Zensical. It is a TRANSITIONAL shim — the
# Zensical maintainers intend native versioning later and will only backport
# compatibility fixes (no new features) to the fork. Install it from GitHub:
#
#   mike deploy --push --update-aliases <version> latest --remote origin-github
#   mike set-default --push latest --remote origin-github   # once: / → latest
#
# It is a git install (not on PyPI), so it is pinned to the release tag's
# commit SHA for reproducible builds. `git` must be on PATH. NOTE: this makes
# the *deploy* path Zensical-only; the mkdocs-material fallback below stays
# available for a plain local/`mkdocs build`, but not for versioned deploys.
#
# One-time repo setting (owner): Settings → Pages → Source:
# "Deploy from a branch" → `gh-pages` → `/ (root)`.
#
# SECONDARY: mkdocs-material — the previous builder, kept as a working
# fallback while Zensical is pre-1.0 (upstream advises gradual, reversible
# adoption). `mkdocs build --strict` still works, but note two differences:
#   * mkdocs.yml's `plugins: - exclude:` is Zensical-only; MkDocs errors with
#     'The "exclude" plugin is not installed'. For a MkDocs fallback build,
#     comment out that plugin and rely on MkDocs' own .gitignore handling
#     (which covers TODO.md and page-level PDFs, but NOT docs/ asset PDFs —
#     see the comment in .gitignore).
#   * MkDocs writes the search index to search/search_index.json; Zensical
#     writes site/search.json. Neither is referenced by hand.
# Drop mkdocs-material once Zensical hits 1.x and has proven out across a
# release cycle or two (re-evaluate after the 0.1.0 community launch).
#
# Pinned for reproducible builds (see .clinerules/toolchain-and-commands.md).
